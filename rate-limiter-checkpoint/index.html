ⓘ DESIGN CHECKPOINT

Rate Limiter 會做出 Allow / Deny 決策。當結果是 Deny 時，應該由 Rate Limiter Service 自己回傳 HTTP 429，還是回傳 200 並交由 Gateway 根據 Verdict 處理？

Rate Limiter 比較像一個「決策服務（Oracle）」，而不是實際承接 Client Request 的 Request Path。它只負責回答 Allow 或 Deny，無論結果為何都可以回傳 200；真正持有 Client Connection 的 Gateway，再把 Deny 轉成 HTTP 429，並加上 Retry-After。

把 429 留在 Gateway 處理，也能讓同一套 Rate Limiter 同時服務 API Gateway、RPC Client 或 Batch Job，讓不同呼叫端依照相同 Verdict 採取不同動作。
